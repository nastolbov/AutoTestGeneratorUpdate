## 1. §1.7 ИСПЫТАНИЯ — целиком новый текст

### 1.7. Выбор стратегии тестирования, разработка тестов, программа и методика испытаний

Программа и методика испытаний разработаны в соответствии с ГОСТ 19.301-79 [24].

#### 1.7.1. Объект и цель испытаний

**Объект испытаний** — информационная система AutoTestGenerator (`autotestgenerator.jar`), реализующая автоматическую генерацию UI-автотестов веб-приложений на платформе E3Core. К объекту относится также порождаемый системой артефакт — Maven-проект `generated-tests/`, содержащий исходный код тестов на JUnit 5 [17] и Page Object Model [21].

**Цель испытаний** — установить соответствие системы требованиям технического задания (Приложение 1) путём прогона сгенерированного тестового проекта на эталонной XML-метамодели подсистемы E3Core, развёрнутой на тестовом стенде `https://rrpo.cmirit.ru/E3Core`.

#### 1.7.2. Требования к информационному, аппаратно-программному обеспечению

##### 1.7.2.1. Требования к функциональным характеристикам

Программа должна обеспечивать выполнение следующих функций:

1. Работу в графическом режиме на платформе JavaFX [16] (CLI-режим из требований исключён).
2. Парсинг XML-метамодели формата E3Core с использованием потокового StAX-парсера [20].
3. Классификацию сущностей модели на три категории: PRIMARY (основная бизнес-сущность), CHILD (дочерняя, отображаемая как Grid-вкладка), REFERENCE_DICTIONARY (справочник).
4. Поддержку трёх уровней детализации генерируемых тестов:
   - SMOKE — базовая проверка наличия полей формы (метод `testFieldsPresent`);
   - BASIC — SMOKE + параметрические поиски (`testSearch*`) + Grid-вкладки (`testGrid*`);
   - FULL — BASIC + операции CRUD (`testCreate`, `testCreateOnlyRequired`, `testUpdate`, `testDelete`, `testLogicalEdit`, `testArchive`) + валидация (`testRequiredFieldValidation`, `testPartialRequiredFieldValidation`).
5. Параллельный режим запуска (fastMode) — три параллельных headless-экземпляра Chrome (Selenium WebDriver [18]) через Maven Surefire `-DforkCount=3 -Dheadless=true`, обеспечивающий ускорение прогона в 3–4 раза.
6. Выборочный запуск подмножества тестов через диалог формирования Surefire-фильтра `-Dtest=Class1#m1+m2,Class2`.
7. Автоматический smoke-обход всех подсистем приложения E3Core при включённой соответствующей опции.
8. Сохранение истории прогонов в локальной базе данных SQLite [19] (`autotestgen.db`).
9. Формирование пользовательского HTML-отчёта v5 с фотолетописью (скриншоты на каждом шаге теста) и CSV-выгрузки.
10. Параллельную генерацию стандартного отчёта Surefire-плагином Maven [15].

##### 1.7.2.2. Требования к надёжности

Программа должна обеспечивать корректную обработку нештатных ситуаций по следующим сценариям:

| Сценарий | Ожидаемая реакция |
| -------- | ----------------- |
| Невалидный XML | Создание исключения `ParserException`, вывод диалога с описанием ошибки, состояние UI не изменяется |
| Отсутствие исходного файла | Вывод диалога «Файл не найден» без аварийного завершения |
| Отсутствие установленного Maven | Перехват `IOException`, передача в `Task.onFailed`, вывод диалога |
| Отсутствие прав записи в каталог вывода | Перехват `IOException` уровня генерации, вывод диалога |
| Сбой записи в SQLite | Перехват `SQLException`, протоколирование в `stderr`, продолжение работы без записи в историю (graceful degradation) |
| Несоответствие версии Chrome / ChromeDriver | Тест помечается статусом FAIL внутри Surefire-отчёта, программа продолжает работу |

#### 1.7.3. Состав, порядок и методы испытаний

Программа испытаний состоит из пяти последовательных этапов; распределение проверяемых модулей по этапам приведено в таблице 1.

## 2. ТЗ (Приложение 1) — обновлённые разделы

### 3.1. Требования к функциональным характеристикам

Программа должна обеспечивать выполнение следующих функций:

- разбор XML-метамодели формата E3Core с применением потокового парсера StAX [20];
- автоматическую классификацию сущностей модели на три категории: PRIMARY, CHILD, REFERENCE_DICTIONARY;
- генерацию исходных кодов Maven-проекта автотестов на JUnit 5 [17] с использованием паттерна Page Object Model [21];
- поддержку трёх уровней детализации: SMOKE, BASIC, FULL;
- параллельный режим запуска тестов через Maven Surefire [15] (`-DforkCount=3 -Dheadless=true`);
- выборочный запуск подмножества тестов через формирование Surefire-фильтра;
- сохранение истории прогонов в локальной базе данных SQLite [19];
- формирование пользовательского HTML-отчёта с фотолетописью и CSV-выгрузки.

### 3.4. Требования к надёжности

Программа должна обеспечивать устойчивую работу при возникновении следующих нештатных ситуаций:

- невалидная структура входного XML — программа выводит сообщение об ошибке без аварийного завершения;
- отсутствие или недоступность исходного файла — программа выводит сообщение и возвращается в исходное состояние;
- отсутствие установленных вспомогательных программных средств (Apache Maven, Google Chrome) — программа выводит сообщение об ошибке при попытке прогона тестов;
- сбой записи в локальную базу данных истории прогонов — программа продолжает работу в режиме без сохранения истории (graceful degradation), о чём выводит соответствующее предупреждение в журнал;
- ошибка в одном из сгенерированных автотестов на стороне браузера — рассматривается как штатный результат тестирования (FAIL), программа продолжает работу.

### 3.6. Требования к информационной и программной совместимости

Программа разрабатывается на языке Java SE 17 [22] и совместима с операционными системами Microsoft Windows 10/11. Программа использует следующие сторонние библиотеки:

- JavaFX версии 24.0.1 [16] — графический интерфейс пользователя;
- SQLite JDBC версии 3.42 [19] — драйвер локальной базы данных;
- встроенный API StAX [20] — потоковый парсинг XML.

Генерируемый Maven-проект использует:

- Apache Maven версии 3.8 и выше [15];
- Selenium WebDriver версии 4.15.0 [18];
- JUnit Jupiter версии 5.10.1 [17];
- WebDriverManager версии 5.6.2;
- Maven Surefire Plugin версии 3.2.2.

Структура программной документации соответствует требованиям ГОСТ 19.402-78 [26]. Техническое задание оформлено в соответствии с ГОСТ 19.201-78 [23].
