# Раздел 1.4.5 — логическая модель базы данных (Рис. 10)

В дипломе раздел 1.4.5 содержит физическую модель БД (таблицы `test_run`, `test_case`
с типами SQLite, табл. 34–35), но не хватало **логической** модели (Рис. 10).

## Логический уровень: что описывается

Логическая модель описывает **информационные сущности**, их **атрибуты**, **ключи**
(первичные/внешние) и **связи** между сущностями — без привязки к СУБД (без физических
типов, индексов, ограничений). Это уровень «какие данные и в каких связях хранятся».
Физическая модель — это уже реализация в конкретной СУБД (таблицы, типы, ключи).

По реальной схеме программы (`ru.autotestgen.data.SchemaInitializer`) выделены
две сущности и связь 1:N:

- **Прогон тестов** (`test_run`) — сведения о запуске набора автотестов;
- **Результат теста** (`test_case`) — результат выполнения одного тест-кейса;
- связь: один прогон **содержит** много результатов (1:N), внешний ключ
  «ИД прогона» в «Результат теста» ссылается на PK «Прогон тестов».

## Файлы
