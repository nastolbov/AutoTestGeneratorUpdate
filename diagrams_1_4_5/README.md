# Раздел 1.4.5 — модель базы данных (логическая + физическая)

Полный фрагмент раздела 1.4.5, построенный по реальной схеме SQLite программы
(`ru.autotestgen.data.SchemaInitializer`). Две таблицы со связью 1:N
(`test_case.run_id → test_run.id`). Имена сущностей и полей — реальные, не переводятся.

## Логический и физический уровни

- **Логическая модель** (Рис. 10) — сущности, атрибуты, ключи и связи без привязки к
  СУБД (без физических типов, ограничений, индексов).
- **Физическая модель** (Рис. 11) — реализация в SQLite: конкретные типы (INTEGER/TEXT),
  динамическая типизация и сродство типов, первичные ключи INTEGER PRIMARY KEY
  AUTOINCREMENT, внешний ключ REFERENCES, ограничения NOT NULL/DEFAULT, нормализация (3НФ).

## Файлы

- `ris_logical_db.png` — логическая ER-диаграмма (ERwin: PK сверху, FK помечен, 1:N);
- `ris_physical_db.png` — физическая ER-диаграмма (типы SQLite, NN, PK/FK);
- `Раздел_1.4.5_модель_БД.docx` — готовый фрагмент: интро + логическая модель
  (Рис. 10, Табл. 34) + развёрнутая физическая модель (Рис. 11, Табл. 35 — test_run,
  Табл. 36 — test_case).

## Нумерация

Табл. **34** — логическая модель, **35** — спецификация test_run, **36** — test_case.
Соответственно последующие таблицы диплома смещаются на +2 относительно исходного
варианта (где физические были 34/35).

## Воспроизведение

```bash
cd scripts
python3 gen_logical_db.py      # ris_logical_db.png + ris_physical_db.png
python3 build_docx_1_4_5.py    # Раздел_1.4.5_модель_БД.docx
```
