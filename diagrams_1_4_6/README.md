# Раздел 1.4.6 — диаграмма переходов состояний (Рис. 12), исправленная

Исходный Рис. 12 в `Столбов_ВКР.docx` был выполнен как блок-схема/диаграмма
деятельности (узлы — действия: «Загрузка XML-модели», «Разбор XML», «Запустить
автотесты», «Сформировать отчёты»…) и **не соответствовал** ни понятию диаграммы
переходов состояний, ни фактической логике программы:

- допускал переход к «Запуску автотестов» прямо из ожидания, тогда как в коде
  (`MainController`) кнопка «Запустить» заблокирована до выполнения разбора и
  генерации — порядок строгий: **разобрать → сгенерировать → запустить**;
- объединял отдельные команды «Разобрать» и «Сгенерировать» в одну ветку;
- не отражал просмотр истории прогонов и обработку ошибок.

Также в тексте раздела упоминались «уровень тестирования» и «подмножество
сущностей» при вводе, хотя в коде уровень зафиксирован (FULL, выбор убран из UI),
а подмножество тестов выбирается только при запуске.

## Исправленная диаграмма

`ris_12_state_transition.png` — диаграмма переходов состояний, построенная по
`MainController`:

| Состояние | Команда / событие → следующее состояние |
|-----------|------------------------------------------|
| Ожидание ввода | «Разобрать метаданные» [файл корректен] → Метаданные разобраны; ошибка разбора → сообщение (остаётся) |
| Метаданные разобраны | «Сгенерировать автотесты» [каталог доступен] → Тесты сгенерированы |
| Тесты сгенерированы | «Запустить автотесты» (запускаются все сгенерированные тесты) → Выполнение тестов |
| Выполнение тестов | прогон завершён / сохранить в БД, HTML, CSV → Результаты получены; ошибка запуска → Тесты сгенерированы |
| Результаты получены | «Запустить снова» → Выполнение тестов; «Просмотреть историю» → Просмотр истории; «Выход» → конец |
| Просмотр истории | «Просмотр результатов теста» → Результаты получены |

Состояния — прямоугольники со скруглёнными углами; начальное состояние —
закрашенный кружок, конечное — кружок с обводкой; переходы подписаны
событием/командой, [условием] и /действием.

## Соответствие методичке (р. 4.2)

По определению методички диаграмма переходов состояний — графическая форма
**конечного автомата**, моделирующего детерминированное поведение системы при
получении **управляющих воздействий (сигналов)**. Диаграмма ему соответствует:
есть состояния, переходы по командам/событиям, детерминированность, начальное и
конечное состояния. Исходный Рис. 12 (блок-схема из действий) этому определению
**не** соответствовал.
