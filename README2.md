# AutoTestGenerator — обновление v3 (auto-discovery + глубокая навигация)

Документ описывает, что изменилось по сравнению с исходной версией в ветке `main`.
Все доработки направлены на повышение покрытия XML-моделей и надёжность авто-тестов,
работающих с веб-интерфейсом E3Core (ExtJS).

## Кратко

- Добавлен **smoke-режим автоматического обхода всех подсистем** XML-модели —
  одной кнопкой запускается генерация и прогон тестов для каждой подсистемы.
- Полностью переписана **навигация по меню E3Core**: теперь поддерживаются
  каскадные подменю ExtJS, склонения русских названий, fallback-кнопка
  «Открыть» и несколько стратегий клика.
- Поиск «по параметрам» теперь действительно открывает форму поиска,
  заполняет её, нажимает «Выполнить поиск» и **проверяет видимость полей
  в гриде результатов** — раньше это был фиктивный smoke.
- Прогон стабилизирован: `forkCount=1`, перезапуск браузера между
  подсистемами, кэширование результата навигации.
- В отчёт выведены **реальные причины пропусков** и сделаны скриншоты
  на каждом сбое — диагностика стала прозрачной.

## Изменения по слоям

### 1. Auto-discovery подсистем (CLI и UI)

- `CliRunner` принимает новые флаги:
  - `--smoke-all-subsystems true|false` (по умолчанию `true`)
  - `--no-smoke` — отключить smoke
- Если `--subsystem` не задан, имя подсистемы автоматически берётся
  из `CategoryName` XML-модели (метод `AppModel.getSubsystemNameFromCategory`).
- В FXML и `MainController` добавлен чекбокс «Smoke-тест всех подсистем»
  для GUI-режима.

### 2. Навигация по меню ExtJS (`TestGenerator.navigateE3Core`)

- Перебираются основные кнопки верхней панели:
  `<подсистема>` → `НСИ` → `Отчёты` → `Сервис`.
- Реализован **рекурсивный `descendMenu`** с ограничением глубины,
  множеством уже посещённых пунктов и корректным повторным поиском
  всплывающего подменю после его перерисовки.
- Между подсистемами браузер перезапускается, чтобы не тащить
  залипшие состояния ExtJS.

### 3. Сопоставление названий по корням слов

- Метод `entityStemPredicate` строит XPath-предикат по корням слов
  (отбрасывает последние 2 символа каждого слова длиннее 3 символов).
- Это позволяет находить пункт меню «Должностные лица» по сущности
  XML «Должностное лицо», «Совещания» по «Совещание» и т.п.
- Помимо «Найти» поддерживается **fallback на «Открыть»** —
  справочники без поиска теперь тоже навигируются.

### 4. Каскадные стратегии клика

Для пунктов меню и кнопок применяются последовательно:
- `WebElement.click()`
- `Actions.click()`
- эмуляция `mousedown`+`mouseup` через JS
- `JavascriptExecutor.click()`

Это обходит характерные баги ExtJS, когда обработчик висит не на `click`,
а на `mousedown`/`mouseup` или на дочернем элементе.

### 5. Поиск «по параметрам»

- В дереве выбора поиска по узлу «по параметрам» делается **double-click** —
  только так ExtJS отрисовывает форму поиска (одиночный клик лишь раскрывает
  узел).
- Кнопка «Выполнить поиск» отбирается по реальным
  атрибутам (`title`, `aria-label`, `data-qtip`, `value`),
  а не по тексту окна с длинным заголовком —
  раньше клик уходил в заголовок диалога.
- Сделан polling кнопки (она появляется не сразу),
  плюс диагностический дамп найденных кандидатов при промахе.

### 6. Реальные ассерты на форме результатов

- Тест `testFieldsPresent` теперь после навигации:
  1. Открывает поиск по параметрам.
  2. Запускает поиск.
  3. Дожидается грида результатов.
  4. Проверяет, что в гриде/заголовках присутствует **хотя бы одно** из ожидаемых полей XML.
- Порог намеренно снижен до ≥1 (а не «все поля»), чтобы тест был стабилен
  при динамической прорисовке колонок ExtJS. **Отсутствующие поля логируются** —
  это видно в отчёте и помогает отлавливать расхождения XML и формы.
- На каждом сбое сохраняется скриншот в `target/screenshots`.

### 7. Стабильность прогона

- `forkCount=1` в `pom.xml` — устранена конкуренция за единственный Chrome.
- `cachedNavigationOk` — повторные тесты по одной сущности не пытаются
  снова открыть меню, если первая навигация уже провалилась
  (`Assumptions.assumeTrue` корректно помечает skip с реальной причиной).
- Сущности без точки входа (вспомогательные таб-гриды у родителей)
  помечаются `@Disabled("…")` с явной причиной, а не молчаливо падают.

### 8. Отчёт и диагностика

- В таблице результатов (`TestRunner`) теперь выводится **настоящая
  причина skip** из текста `Assumption` JUnit, а не общий «Skipped».
- На сбоях навигации/клика делаются скриншоты + дамп визуально доступных
  пунктов меню в stdout — найти расхождение XML ↔ UI стало быстрее.

### 9. Прочее

- Добавлен `.gitignore` (исключены `target/`, `*.db`, IDE-файлы).
- Singular-сущности, у которых plural уже содержит self-grid, больше не
  помечаются `@Disabled` (фикс ложного «нет точки входа»).

## Известные ограничения

- Часть пунктов меню в подсистеме «Гаражно-строительные кооперативы»
  (например, «Повестка совещания», «Справочник Да/Нет», «Улица») в текущей
  версии стенда находится не в стандартных ветках меню —
  для них навигация продолжает помечать тесты как skip с понятной причиной.
  Лечится либо расширением списка ветвей меню в `navigateE3Core`,
  либо предоставлением соответствующих скриншотов меню для уточнения путей.
- Тесты для дочерних сущностей (History/Document) генерируются как
  отдельные классы — их рекомендуется в дальнейшем встроить как
  таб-гриды родителя.
