# Аудит §1.7 «Тестирование» и Приложения 1 «ТЗ» против vers2

## 0. Ключевой факт

**Наша программа НЕ имеет собственных юнит-тестов** — `src/test/` отсутствует.
Программа AutoTestGenerator — это **генератор автотестов**: она производит **выходной артефакт** (Maven-проект), который потом сам выполняет тесты на реальной системе E3Core.

Это меняет подход к описанию тестирования в дипломе:
- **Объект испытаний** = система AutoTestGenerator + её выходной артефакт (сгенерированный проект)
- **Методы испытаний** = функциональное (чёрный ящик) на реальном тестовом стенде E3Core
- **Критерий приёмки** = успешный прогон сгенерированных тестов на эталонной XML-модели

3. Эталонная XML-модель подсистемы (например, «Гаражно-строительные кооперативы»)

| № | Требование |
| - | ---------- |
| 1 | Программа должна работать только в **GUI-режиме** (JavaFX) — `mvn javafx:run`. CLI-режим исключён из требований. |

|   | • **SMOKE** — только проверка наличия полей формы (`testFieldsPresent`) |

| 6 | **Выборочный запуск** через диалог «Выбрать тесты…» — формирует Surefire-фильтр `-Dtest=Class1#m1+m2,Class2`. |
| 7 | **Сохранение истории** прогонов в SQLite (`autotestgen.db`). |
| 8 | **Smoke-обход всех подсистем** E3Core (если включена галка). |
| 9 | Формирование **HTML-отчёта v5** с фотолетописью (скриншоты на каждом шаге) + CSV-выгрузка. |
| 10 | **Стандартный отчёт Surefire** также генерируется параллельно. |

## 3. §1.7.2.2 Требования к надёжности

### Что должно быть

| Сценарий ошибки | Реакция программы | Где реализовано |
| --------------- | ----------------- | --------------- |
| Невалидный XML | `ParserException` + `Alert("Ошибка парсинга")` | `XmlModelParser.parse()` |
| Файл не найден | `Alert("Файл не найден")` без падения | `MainController.onParse()` |
| Maven не установлен | `IOException` → `Task.onFailed` → `Alert` | `TestRunner.run()` |
| Нет прав на запись | `IOException` → `Alert("Ошибка генерации")` | `TestGenerator.generate()` |
| Сбой SQLite | `SQLException` ловится, лог в `stderr`, программа продолжает (graceful degradation) | `ReportDao.saveRun()`, `SchemaInitializer.initialize()` |
| Падение Chrome / ChromeDriver mismatch | Помечается FAIL внутри сгенерированного теста; программа не падает | автоматически через Surefire-XML |

## 5. §1.7.3 Состав, порядок и методы испытаний

### Что должно быть

**Метод тестирования** — функциональный (чёрный ящик):
- Тестируется ПОВЕДЕНИЕ системы на эталонной XML-модели, а не внутренние реализации классов.
- Корректность проверяется по успешности прогона сгенерированных автотестов на стенде E3Core.

**Порядок испытаний (5 этапов):**

| Этап | Действие | Критерий приёмки |
| ---- | -------- | ---------------- |
| 1. Парсинг | Загрузить эталонную XML-модель (подсистема ГСК/ОГСК — 19 сущностей) | В журнале: «XML разобран успешно. Найдено сущностей: 19, поисков: M» |
| 2. Классификация | `EntityClassifier` определяет роль каждой сущности | Из 19: ~8 PRIMARY → генерируются тест-классы; CHILD и REFERENCE_DICTIONARY → пропускаются |
| 3. Генерация | Создать Maven-проект для уровней SMOKE / BASIC / FULL | `pom.xml`, `BaseTest.java`, `SharedDriver.java`, `*Page.java`, `*Test.java` — все компилируются |
| 4. Прогон | `mvn test` (последовательный и параллельный fastMode) | Surefire-XML создаётся, ≥80% тестов PASSED |
| 5. Отчётность | Сохранение в SQLite + HTML/CSV-отчёты | `autotestgen.db` пополняется записью, в `target/run-report.html` ≥1 скриншот на тест |

### Из «Модульной структуры» — какие модули проверяются на каждом этапе

| Этап | Тестируемые модули (из 24 поведенческих) |
| ---- | ---------------------------------------- |
| 1. Парсинг | `XmlModelParser`, `EntityParser`, `PropertyGroupParser`, `SearchParser`, `StaxUtils`, `XmlNamespaces`, `ParserException` |
| 2. Классификация | `EntityClassifier` |
| 3. Генерация | `TestGenerator`, `PageObjectWriter`, `TestClassWriter`, `TestDataFactory`, `JavaFileWriter`, `Transliterator`, `TestConfig` |
| 4. Прогон | `TestRunner` (ProcessBuilder + StAX-парсинг Surefire-XML) |
| 5. Отчётность | `ReportDao`, `DatabaseConnection`, `SchemaInitializer`, `TestRunDao`, `TestCaseDao`, `RunReportWriter` |
| Сквозные | `App`, `MainController` (GUI), POJO-классы пакета `model` |
