**Особенности стиля Сафиуллина:**
- Только **3 раздела** — никаких «Условия выполнения», «Установка», «Запуск» отдельно.
- Все требования к среде вынесены в основной раздел ТЗ — в руководстве не дублируются.
- В п.1 функции **сгруппированы по 4 категориям**, не сплошным списком.
- В п.3 рисунков **много** (~12), каждый шаг работы проиллюстрирован отдельным скриншотом.
- Подписи рисунков нумеруются как «Рис. П4.N».

## Что у тебя сейчас (Приложение 4)

```
1. Назначение программы           ← аналог «Общие сведения»
2. Условия выполнения             ← ЛИШНЕЕ (дублирует ТЗ)
3. Установка программы            ← ЛИШНЕЕ (одна строка «не требует установки»)
4. Запуск программы               ← одна команда mvn javafx:run, можно слить с п.3
5. Работа с программой в графическом режиме
   5.1 Главное окно
   5.2 Ввод параметров
   5.3 Разбор XML
   5.4 Генерация тестов
   5.5 Запуск тестов
   5.6 Просмотр истории
```

**Проблемы:**
1. **Структура раздулась** до 5 пунктов вместо 3-х. Сафи держится 3-х.
2. **Дублирование ТЗ** в п.2 «Условия выполнения». У тебя те же требования уже есть в 1.7.2.3.
3. **Назначение программы** — всего 4 буллета функций. У Сафи — 16 пунктов в 4 группах.
4. **Подписи рисунков «Рис. П3.X»** — у тебя ошибка в номере приложения, должно быть **П4.X**.
5. **Мало иллюстраций** — 5 рисунков на 6 шагов. У Сафи ~12.

## Как переделать — целевая структура

### ПРИЛОЖЕНИЕ 4
### Руководство пользователя

#### 1. Общие сведения о программе

> Информационная система AutoTestGenerator представляет собой настольное приложение для автоматической генерации UI-автотестов веб-приложений, построенных на платформе E3Core, на основе XML-метамодели приложения. Система позволяет инженеру-тестировщику получить готовый Maven-проект автотестов на JUnit 5 и Selenium WebDriver без ручного написания кода, запустить прогон и получить отчёт с фотолетописью прохождения каждого теста.

> Информационная система выполняет следующие функции:

> **Разбор XML-метамодели:**
> - анализ структуры XML-файла формата E3Core с поддержкой трёх пространств имён (NS_E, NS_E3, NS_MD);
> - извлечение информации о сущностях, атрибутах, типах данных, операциях и ассоциациях;
> - транслитерация русских имён сущностей в валидные Java-идентификаторы;
> - классификация сущностей на категории PRIMARY (основная), CHILD (дочерняя), REFERENCE_DICTIONARY (справочник);
> - визуализация списка разобранных сущностей в левой панели главного окна.

> **Генерация тестового проекта:**
> - формирование Maven-проекта с файлом pom.xml и зависимостями Selenium WebDriver, JUnit 5, WebDriverManager;
> - генерация общих классов SharedDriver, BaseTest, TestData;
> - генерация Page Object класса для каждой PRIMARY-сущности модели;
> - генерация тестового класса JUnit 5 для каждой PRIMARY-сущности;
> - поддержка трёх уровней покрытия: SMOKE (проверка наличия полей), BASIC (+ поиск и таблица), FULL (+ полный CRUD-цикл).

> **Запуск тестов и сбор результатов:**
> - запуск сгенерированных автотестов через системный вызов `mvn test`;
> - параллельный режим (fastMode) с тремя headless-экземплярами Chrome для ускорения прогона;
> - выборочный запуск подмножества тестов через фильтр Surefire;
> - построчный вывод хода выполнения в журнале работы;
> - сбор результатов из XML-отчётов Surefire с разделением на passed / failed / skipped.

> **Хранение и отображение истории:**
> - сохранение каждого прогона в локальную базу данных SQLite в рамках одной транзакции;
> - автоматическое создание базы данных при первом запуске и сохранение между сеансами;
> - просмотр истории прошлых прогонов в журнале главного окна;
> - формирование HTML-отчёта с фотолетописью (скриншоты на каждом шаге теста) и CSV-выгрузки результатов.

#### 2. Описание запуска

> Для запуска приложения необходимо открыть командную строку в корневом каталоге проекта `AutoTestGenerator` и выполнить команду `mvn javafx:run` (рис. П4.1). После запуска отображается главное окно приложения в начальном состоянии (рис. П4.2).
>
> *Рис. П4.1. Запуск приложения командой `mvn javafx:run`*
>
> *Рис. П4.2. Главное окно приложения в начальном состоянии*

#### 3. Работа с программой

> **Шаг 1. Ввод параметров.** В верхней панели главного окна заполнить поля: «XML-файл» — путь к файлу метамодели; «URL сайта» — адрес тестируемого веб-приложения; «Логин» и «Пароль» — учётные данные для авторизации; «Каталог вывода» — директория для Maven-проекта; «Уровень тестов» — выпадающий список SMOKE / BASIC / FULL. Поля «XML-файл» и «Каталог вывода» можно заполнить через диалог «Обзор…» (рис. П4.3).
>
> *Рис. П4.3. Диалог выбора XML-файла*

> **Шаг 2. Разбор XML-модели.** Нажать кнопку «Разобрать XML». Система выполнит потоковый разбор файла в фоновом потоке, по завершении в левой панели «Сущности модели» отобразится список разобранных сущностей (рис. П4.4). Для каждой сущности показаны её имя и категория. В случае ошибки разбора будет показано модальное окно с сообщением (рис. П4.5).
>
> *Рис. П4.4. Список разобранных сущностей*
>
> *Рис. П4.5. Сообщение об ошибке разбора*

> **Шаг 3. Генерация тестового проекта.** Нажать кнопку «Сгенерировать тесты». В указанном каталоге будет создан Maven-проект, включающий pom.xml, общие классы (SharedDriver, BaseTest, TestData), Page Object и тестовый класс для каждой PRIMARY-сущности. По завершении в журнале работы появляется сообщение с количеством сгенерированных файлов (рис. П4.6).
>
> *Рис. П4.6. Журнал после генерации тестов*

> **Шаг 4. Запуск тестов.** Нажать кнопку «Запустить тесты». При необходимости отметить флажок «Параллельный режим» для ускоренного прогона в headless-режиме либо указать фильтр для выборочного запуска. Система запускает команду `mvn test` в фоновом потоке, построчный вывод отображается в нижней панели «Журнал работы» (рис. П4.7).
>
> *Рис. П4.7. Журнал работы Maven при запуске тестов*

> **Шаг 5. Просмотр результатов прогона.** По завершении прогона центральная таблица результатов заполняется записями: имя класса, имя метода, статус (PASSED / FAILED / SKIPPED), длительность, сообщение об ошибке (рис. П4.8). Двойной клик по строке открывает детальную карточку теста со скриншотами (рис. П4.9).
>
> *Рис. П4.8. Таблица результатов прогона*
>
> *Рис. П4.9. Карточка теста со скриншотами*

> **Шаг 6. Просмотр истории прогонов.** Для просмотра ранее выполненных прогонов нажать кнопку «История прогонов». В журнале работы отобразится список всех сохранённых прогонов с датой, именем XML-файла, URL стенда и итоговой статистикой (passed / failed / skipped). Выбор записи открывает соответствующие XML-отчёты и скриншоты этого прогона (рис. П4.10).
>
> *Рис. П4.10. Просмотр истории прогонов*

> **Шаг 7. Открытие HTML-отчёта.** По завершении прогона в каталоге `target/` сгенерированного Maven-проекта создаётся файл `run-report.html` — пользовательский HTML-отчёт с фотолетописью (скриншоты на каждом шаге каждого теста) и кнопкой выгрузки результатов в CSV (рис. П4.11–П4.12).
>
> *Рис. П4.11. HTML-отчёт с фотолетописью*
>
> *Рис. П4.12. CSV-выгрузка результатов*
